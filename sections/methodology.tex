\section{Methodology}
\label{sec:methodology}

This Chapter outlines the Four-stage Analytical Pipeline that will be utilized to compare whether Instruction Tuning has introduced New Features into a Language Model's Internal Representations as opposed to Simply Reorganizing Existing Ones to Align Directly with the Research Question Presented in \S\ref{subsubsec:gap-rq}. This Chapter focuses on Methodology; what is being Measured, How the Four-way Classification is Constructed, and What Specific Settings Will be Used to Compare. Stage One (Sections~\ref{subsec:models-saes}--\ref{subsec:activation-collection}) Selects the Same Architecture and Layer for Both Pre-Trained and Instruction-Tuned Variants of the Model Pairs Using Matched Sparse AutoEncoders, and Collects Activation Data from the Same Activation Corpus. Stage Two (Sections~\ref{subsec:feature-matching-classification}--\ref{subsec:threshold-selection}) Establishes a Feature-Level Correspondence Between the Activations of the Two Checkpoints Based Upon Decoder Direction Similarity and Activation Correlation, and Utilizes a Threshold Grid to Determine Whether the Resulting Four-way Partition (Preserved, Modified, PT-Exclusive, IT-Exclusive) is Not Due to a Single Threshold Choice. Stage Three (\S\ref{subsec:automated-labelling}) Provides Descriptive Vocabulary to Sampled Features Through Automated Dual-LLM Labelling with Consensus Construction, Providing the Interpretive Layer Needed to Discuss What Features Mean, and an Inter-Annotator Reliability Check. Finally, Stage Four (\S\ref{subsec:targeted-differential-analysis}) Grounds the Classification in Behavioural Prompts by Computing Targeted Differential Activations for a Safety Contrast (JailbreakBench Harmful vs Benign), and an Instruction Following Contrast (Stanford Alpaca vs TruthfulQA), Using Welch's $t$-tests.

\subsection{Stage 1: Model Selection and Sparse Autoencoders}
\label{subsec:models-saes}

The test subject is the Gemma 3 1B model family from Google. This includes the pre-trained base checkpoint \path{google/gemma-3-1b-pt} and the instruction-tuned version \path{google/gemma-3-1b-it}. The models have the same architecture (26 transformer layers with hidden dimension 1152) and were loaded using HuggingFace \texttt{transformers} in \texttt{bfloat16} format. We selected the smaller scale (1B), since it can be fitted within a single commodity GPU, which enables reproducibility and improves iteration speed. Furthermore, this is the smallest scale at which publicly accessible SAEs exist for both base and instruction-tuned checkpoints of the same architecture, through Gemma Scope~2 \parencite{mcdougall_gemma_scope_2_2025}. In addition, we had originally planned to test the Gemma 2 2B model, but this option was eliminated due to the lack of an instruction-tuned checkpoint with a corresponding SAE. Without SAEs that pair PT/IT at the same layer and width, the main study could not be defended based on methodology.

In particular, the SAEs used here came from Gemma Scope 2. Following other SAE studies treating residual-stream activations as a combination of sparse interpretable feature directions \parencite{cunningham_sparse_2023,bricken_monosemanticity_2023,elhage_toy_2022}, \texttt{gemma-scope-2-1b-pt-res} was used for the base model and \texttt{gemma-scope-2-1b-it-res} for the instruction-tuned model, both at the \texttt{layer\_13\_width\_16k\_l0\_medium} configuration. Both SAEs use the JumpReLU encoder of \textcite{rajamanoharan_improving_2024}, have a dictionary width of 16,384 features, and were trained by Google DeepMind at comparable expected $L_0$ sparsity. As such, they are directly comparable as feature dictionaries for the same architecture.

Layer 13 was selected because of its position at the middle of the 26-layer stack, where prior research on Gemma Scope and residual-stream SAEs reports the richest mixture of syntactic and semantic features. The middle layers tend to exhibit the richest collection of abstract features relevant to downstream behaviour, while earlier layers are dominated by token-level and syntactic features and later layers by output-oriented features. This was a scoping decision, not a methodological statement, and its implications for generalisation are addressed in Chapter~\ref{sec:discussion}. One implementation issue worth noting is that Gemma 3 1B required \texttt{bfloat16} rather than \texttt{float16} for inference: the narrower dynamic range of \texttt{float16} produced overflow-driven NaN activations during early testing and would have silently corrupted the activation buffer.

\subsection{Stage 1: Activation Collection}
\label{subsec:activation-collection}

The activation corpus consisted of 5,000 sequences randomly selected from the HuggingFace \path{HuggingFaceFW/fineweb} dataset (\path{sample-10BT} split), accessed via \texttt{streaming} mode with a single random seed for reproducibility. Each sequence was tokenized with the shared Gemma tokenizer and shortened to exactly 256 tokens. Any sequence less than 256 tokens was removed instead of being padded, thus every remaining sequence contributed the same number of activation rows without needing to apply padding masks. This number of sequences was chosen based on the pilot study which found that SAE feature statistic (activation frequency, mean activation, per-sequence mean activation vectors used in \S\ref{subsec:feature-matching-classification}), stabilized under much fewer than 50,000 sequences and further data did not qualitatively alter the results but significantly increased run times. The total corpus contains roughly 1.275 million activation rows per model (5,000 sequences $\times$ 255 tokens after dropping the first token of each sequence as explained below).

Activation values for both models were collected from layer 13 of each model's residual stream output using a PyTorch forward hook registered on the corresponding \path{model.model.layers[13]} module. The sequences were processed in batches of four and each batch had the first token of each sequence dropped prior to processing using the SAE. The reason for dropping the first token is that it has no contextual information from any other token in a causal transformer and therefore produces abnormal activation statistics. The resulting activation matrix was then transferred into CPU memory in \texttt{float32} and re-encoded through the SAE in chunks of 64 rows at a time. Chunked encoding was needed since attempting to encode the complete activation matrix in a single GPU operation resulted in out-of-memory conditions when using a 16,384-wide feature dictionary. Additionally, processing one sequence at a time would have been far too slow to be practical. During each chunk, the SAE encoder, decoder, and reconstruction residual were calculated. Three running statistics were also updated per feature during this process: the sum of activations, the sum of squared activations, and the count of non-zero activations. After all batches were processed these running statistics were used to calculate the per-feature mean activation $\bar{f}_i$, and activation frequency $\rho_i$. A per-sequence mean activation vector was also calculated for each sequence. As a result, a matrix with dimensions $5000 \times 16384$ was generated. This matrix was later used as input to the activation correlation step of \S\ref{subsec:feature-matching-classification}. Two quality metrics for the SAE were also tracked during encoding: FVU (fraction of variance unexplained) for the reconstruction and mean $L_0$ count (average number of non-zero features per activation row). Both of these were printed at the completion of each encoding pass as sanity checks to ensure that the pre-trained SAEs were operating within their anticipated regimes on the FineWeb corpus rather than failing silently.

As outputs of this phase, for each model, there exists a summary of how the SAE features behave across the corpus: activation frequency, mean activation, per-sequence mean activation vectors, and SAE decoder matrices (which are loaded once and reused). These four objects comprise the only inputs required for the feature matching and classification phase described in the section immediately below.

\subsection{Stage 2: Feature Matching and Four-Way Classification}
\label{subsec:feature-matching-classification}

The principal methodology construct that we employ is a four-way categorization system that identifies SAE features as being either preserved, modified, PT-exclusive or IT-exclusive based upon two complimentary measures of similarity. These measures are decoder direction similarity and activation correlation. Decoder direction similarity measures how similar the two dictionaries' "direction" are within residual stream space. Activation correlation measures how similar the matched features are utilized by the common FineWeb corpus. By employing both measures simultaneously and having the stronger category (preserved) agree between them eliminates some of the individual weakness of either measure.

Decoder direction similarity is calculated through the use of the PT and IT decoder matrices, $D^{\mathrm{PT}} \in \mathbb{R}^{F \times d}$ and $D^{\mathrm{IT}} \in \mathbb{R}^{F \times d}$, where all rows have been normalized via $\ell_2$ normalization. Then we can compute the cosine similarity matrix as $S = D^{\mathrm{PT}}(D^{\mathrm{IT}})^{\top}$. We find the best match for every PT feature $i$ as $j^{*}(i) = \arg\max_j S_{ij}$ and find the best match for every IT feature $j$. To do this, we also calculate the maximum cosine similarity $s^{\mathrm{max}}_i$. The same process is performed in reverse to obtain the best match for every IT feature $j$. This bi-directional matching is important since PT-to-IT and IT-to-PT nearest neighbors may be different.

To calculate activation correlation, we use the collection of mean activation matrices described in \S\ref{subsec:activation-collection}. For every feature, along with it's closest geometric match in another dictionary, we will compute the Pearson correlation coefficient of the vector of activations per sequence for the given feature and it's corresponding geometric match. Again, we include a numeric check for features with zero variance. In addition to providing an indication of whether or not a feature and it's nearest neighbor in another dictionary are functionally correlated on the same set of input sequences, we perform this calculation in the reverse direction as well for IT features.

Now that we have defined both measures, we define our four-way classification system using both measures at thresholds $(\tau_d,\tau_a)$. Specifically, a PT feature $i$ is said to be \textit{preserved} when both conditions $s^{\mathrm{max}}_i \geq \tau_d$ and $\rho_i \geq \tau_a$ hold. If only one of the conditions hold, the feature is said to be \textit{modified}. Otherwise, if none of the conditions hold, the feature is classified as \textit{PT-exclisive}. As previously stated, we classify an IT feature using a symmetrical approach using the reversed-direction matches and their activation correlation values. Analysis is restricted to \textit{active} features with activation frequency above 0.1\% of tokens, which removes dead features without materially constraining the category distribution.

\subsection{Stage 2: Threshold Selection and Sensitivity Analysis}
\label{subsec:threshold-selection}

The classification will depend upon two free variables $\tau_{d}$ and $\tau_{a}$; therefore, the entire process will be recalculated using a $25$-point grid of $\tau_{d}\in\left\{0.5,0.6,0.7,0.8,0.9\right\}$ and $\tau_{a}\in\left\{0.1,0.2,0.3,0.5,0.7\right\}$. For every pair of values ($\tau_{d},\tau_{a}$), we will collect all the numbers describing preserved and modified cells and cells exclusively classified by PT or IT together with their respective preservation and modification rates and present them as heat maps. Our goal here is to provide evidence for robustness rather than optimalization: We want to demonstrate that the qualitative characteristics of the classification remain unchanged over a wide range of reasonable threshold values.

The primary operating point for the interpretive phases (Subsections~\ref{subsec:automated-labelling} and \ref{subsec:targeted-differential-analysis}) is $\tau_d=0.7$, $\tau_a=0.3$, selected after the sensitivity grid was computed because it lies in the interior of the grid and represents a moderate standard of both geometric and functional correspondence. Stricter settings collapse the preserved set and inflate the exclusive categories, while more permissive settings blur the distinction between modified and preserved. The full grid in \S\ref{subsec:feature-classification-threshold-robustness} serves as the robustness check.

\subsection{Stage 3: Automated Feature Labelling and Consensus Construction}
\label{subsec:automated-labelling}

The use of two LLM models was made intentional: as it is hard to validate the labels assigned by a single model, the use of two independent models, Claude Haiku 4.5 \parencite{anthropic_haiku_2025} and GPT-5.4-nano, provides an inter-annotator reliability test and makes disagreements between the models visible to analysis.
Sampling was done based upon activation frequencies rather than uniform sampling. This ensures that those activated most often during the computation process are given priority for labeling, whereas rarely activated features are not labeled since they are likely noisy and difficult to understand.
For each sampled feature, the top 20 activating token contexts are identified. These contexts are generated by running the appropriate model and SAE on the first 1,000 of the 5,000-sequence FineWeb corpus used in Stage 1. Per-token activation values are determined through processing the output of the previous step. In addition, all high-activation positions are kept along with a window of 8 tokens around them to provide additional context. The activating token itself is clearly indicated using \texttt{>>>} and \texttt{<<<} delimiters in order to allow the labeling model to accurately determine the position at which the feature activates. This delimiter approach is consistent with the presentation style used in Anthropic monosemanticity research and later SAE labeling pipeline processes.

Both models receive the same input prompts and produce output that has been formatted similarly, so that any variance in the output of the two models can be attributed to the respective models themselves and not due to variations in the prompts provided. Each model receives a prompt that requests that they act as a neural network interpretation expert. The prompt also identifies the 20 top-activated contexts associated with a feature. Finally, it asks for three types of information: a brief (one-to-two sentences) description of the detected pattern, a single label from a six-way categorization (\path{language_syntax}, \path{knowledge_semantics}, \path{instruction_style}, \path{safety_alignment}, \path{formatting}, \path{other}) and a confidence level rated from 1 to 5. Output is restricted to this schema via the use of structured output interfaces available through both the Anthropic and OpenAI software development kits (\path{client.messages.parse} with a Pydantic \texttt{FeatureLabel} schema for Haiku, \path{client.beta.chat.completions.parse} with the corresponding schema for GPT).
Structured output formats were critical: prior versions that allowed for free text entries resulted in highly variable category names (``syntax'', ``grammatical'', ``semantic'') that required ad hoc normalization. With structured output formats, category names were consistently formatted and thus could easily be compared between models. Labeling occurred in a category-by-category fashion with rate-limiting sleeps between calls. Labels were serialized to disk as JSON after completion of each category.

To construct consensus among the two labeling models, we applied the following rules: when both models assign the same category, we consider this a consensus case, where this category is selected as the consensus category for that feature. When both models select different categories, we then select the category from the model that reported a greater confidence value for that feature as the consensus category. In cases where both models report equally confident values for a particular category assignment, we select Haiku as our primary model and GPT as our secondary model. In addition to assigning a consensus label for each feature based upon how well the two models agreed or disagreed on assignments, we retained both descriptions and both confidence levels for each feature as part of the record. Thus, disagreement cases may be examined qualitatively versus merely being tallied. As will be described in detail in \S\ref{subsec:automated-labelling-inter-annotator-agreement}, these consensus labels enable us to create two very different analyses in Chapter~\ref{sec:results}: first, the proportion of agreement and disagreement/confusion matrices for the two models will serve as an inter-annotator reliability metric for assessing whether there exists any stability in terms of consistency to this six-way taxonomy; second, the distribution of categories in terms of their proportions among the four feature classes for features assigned within the agreement set will form the basis of our discussion regarding what types of features are preserved, modified or exclusive to each checkpoint.

\subsection{Stage 4: Targeted Differential Analysis on Behavioural Probes}
\label{subsec:targeted-differential-analysis}

The labelling stage associates labels or descriptive vocabulary to specific features; however, this process alone does not confirm whether any of these features impact the behaviors that the instructional tuning is intended to promote. A targeted differential analysis is therefore conducted to relate the classification of the behaviorally relevant features to actual behavioral changes. The differential analysis utilizes two behavioral contrasts with three external probe data sets: JailbreakBench \parencite{chao_jailbreakbench_2024} for the safety contrast, Stanford Alpaca \parencite{taori_stanford_alpaca_2023} for the instruction-shaped prompts, and TruthfulQA \parencite{lin_truthfulqa_2022} as the factual contrast set for the instruction-following comparison.

In the context of the specific study reported herein, the safety contrast utilizes 100 harmful and 100 benign JailbreakBench prompts. The instruction contrast utilized the first 200 Alpaca prompts against 200 TruthfulQA questions in the generation split.
It is important to note that the design of the contrasts is significant. For the purposes of safety, harmfully-split JailbreakBench prompts were compared to benignly-split prompts within the same JailbreakBench data set. Therefore, the differential activation isolated only safety-relevant structure, and did not isolate stylistic differences between task-based prompts and web-text. For the purposes of instruction, Alpaca prompts were compared to TruthfulQA questions to create a contrast between imperative task-based prompts and interrogative factual query-based prompts.

For each contrast and each of the two models, SAE feature activations were calculated for each prompt utilizing an identical activation collection procedure as described in \S\ref{subsec:activation-collection}; however, with a reduced max sequence length of 128 tokens as applicable to probe prompts, and with per-prompt feature statistics rather than per-sequence feature statistics. Per-prompt activation was defined as the average of token-level activations for a given feature across all non-first tokens in a prompt. Each per-prompt activation was recorded as a row in a prompts $\times$ features matrix per model.
Two such matrices were created per model: one for safety vs.\ benign comparisons and another for instruction vs.\ truthful comparisons. All further analysis was conducted on a feature-by-feature basis on these matrices.

A Welch's two-sample $t$-test \parencite{welch_generalization_1947} was applied for each feature to compare its per-prompt activations for the target group (i.e., harmful prompts) versus the contrast group (benign prompts). A Welch's $t$-test was employed instead of a standard equal-variance $t$-test since there could be no assumption made regarding equal variance across the two groups. By definition, a feature that selectively activates on harmful prompts will also vary more on the group where it is activated, as opposed to when it is not. The implementation utilized \texttt{scipy.stats.ttest\_ind} with \texttt{equal\_var=False}.

Features were considered differentially activated if both conditions were met:
\begin{enumerate}
    \item The $p$-value for a $t$-test $< 0.01$.
    \item The mean activation on the target group $> 0.01$ (this serves as a floor value to prevent a large number of features that are statistically different simply due to having very low baseline activation levels).
\end{enumerate}

Upon meeting both conditions, the pipeline documented for each differentially activated feature its respective feature index, mean activations for both the target and contrast groups, their difference and ratio, as well as test statistic and $p$-value. The top 30 differential features for each contrast per model are subsequently ranked according to their absolute difference values and forwarded to the automated labeling pipeline in \S\ref{subsec:automated-labelling}. This labeling process reapplied the labels provided during training using probes drawn directly from the prompts of the probes rather than those found in FineWeb. As such, this step enabled the results of \S\ref{subsec:targeted-differential-analysis-results} to describe not only which features were differentially activated but what they appeared to recognize.
