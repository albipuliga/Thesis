## Executive Summary

When a language model is deployed as a chatbot or assistant, it behaves very differently from the raw model that came out of pre-training. It follows instructions, refuses harmful requests, and adopts a conversational tone. These behaviours are introduced during post-training, a set of fine-tuning stages applied after the initial next-token-prediction training. A basic question about this process remains open: does post-training install genuinely new computational structure inside the model, or does it mostly re-arrange what the base model already learned? The answer matters for safety. If safety behaviours are only a thin layer on top of existing capabilities, they may be easier to bypass or undo than if they were built from new internal machinery.

Most interpretability work to date has studied base models, not the changes introduced by post-training. The debate has instead been shaped by behavioural observations. The LIMA result showed that very few high-quality training examples can produce strong instruction-following, hinting that the base model already contains what it needs and post-training merely surfaces it. Some alignment research, on the other hand, implicitly assumes that post-training creates new circuits or features. Testing these positions at the level of internal representations was difficult until recently because no tool existed for directly comparing the full feature-level state of two model checkpoints.

Sparse Autoencoders (SAEs) changed this. SAEs decompose a model's internal activations into dictionaries of interpretable features, where each feature is a direction in activation space that tends to fire on semantically coherent patterns. Google DeepMind's Gemma Scope 2 release included matched SAE dictionaries for both the base and instruction-tuned versions of Gemma 3 1B, trained at the same layer and dictionary width. This made it possible, for the first time, to line up the feature dictionaries of a real pre-trained model and its instruction-tuned counterpart and ask: which features survived, which changed, and which are entirely new?

This thesis built a four-stage pipeline to answer that question. First, activations were collected from layer 13 of both model versions across 5,000 web-text sequences, yielding roughly 1.28 million activation vectors per model. Second, each feature in one dictionary was matched to its closest counterpart in the other using two complementary measures: geometric similarity of the decoder directions and correlation of their activation patterns across the shared corpus. Based on these scores, every active feature was sorted into one of four bins (preserved, modified, PT-exclusive, or IT-exclusive). A grid of 25 threshold combinations confirmed the classification was not an artifact of any single cutoff. Third, a sample of features from each bin was labelled by two independent LLMs (Claude Haiku 4.5 and GPT-5.4-nano) to assign semantic categories, with disagreements resolved by confidence scores. This provided both interpretive vocabulary and a reliability check. Fourth, the classification was connected to actual model behaviour by running both models on safety prompts (JailbreakBench) and instruction-following prompts (Stanford Alpaca vs. TruthfulQA) and identifying which features showed the largest differential activation between target and control groups.

At the chosen operating point, only 241 features qualified as preserved, while over 4,000 fell into the modified category. This imbalance held across all 25 threshold settings. The labelling stage showed that preserved features were almost entirely low-level linguistic patterns like punctuation and syntax, while features sensitive to instruction-shaped input appeared in the modified bin, not the preserved or exclusive ones. The behavioural probes were the most telling: the features that responded most strongly to instruction-following prompts in the fine-tuned model were largely the same feature indices that responded most strongly in the base model, just with amplified activation magnitudes. Two specific features (indices 2006 and 446) ranked in the top 5 for both models on the instruction contrast. The safety probe showed a parallel pattern: every one of the top 20 safety-relevant features in the instruction-tuned model had a counterpart in the base model dictionary. None were exclusive to the fine-tuned version.

These findings are the first feature-level evidence from a production-class language model consistent with the "wrapper hypothesis" proposed by Jain et al. (2024), previously tested only in synthetic settings. The data does not support the strong claim that no new features exist, since the IT-exclusive bin is not empty. What it does show is that the features most responsible for instruction-following and safety behaviours are not new creations but adjusted versions of features the base model already had. Instruction tuning amplifies and sharpens pre-existing selectivity rather than producing new detectors.

If this pattern generalises beyond a single model and layer, it is practically important for alignment. Auditing the base model's feature space could reveal the ceiling of what any fine-tuned version can represent, since re-weighting alone cannot create features that were absent from the base model. It also suggests safety behaviours may be more fragile than they appear: if they rest on re-weighted features rather than dedicated new structure, further training on unrelated tasks could plausibly erode them. The main limitation is that the evidence is correlational, showing which features activate on relevant prompts but not that they causally drive the model's outputs. Causal validation through targeted feature steering is the most important next step, followed by replication across multiple layers and other model families.
